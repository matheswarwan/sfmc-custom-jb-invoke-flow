# Salesforce contract verification

Checked against official Salesforce documentation on 2026-09-07. These references verify the documented API contract, not live behavior in a tenant.

- [Postmonger Events Reference](https://developer.salesforce.com/docs/marketing/marketing-cloud/guide/using-postmonger): initial ready produces initActivity with default or saved activity data. requestTriggerEventDefinition returns requestedTriggerEventDefinition after a successful request; its payload is the Entry Source Event Definition Model or null. A field schema is not guaranteed. The application registers listeners first and handles non-response with a retry state.
- The same reference defines updateButton (next text can be done), clickedNext, and updateActivity. Valid save emits the entire activity with metaData.isConfigured true; invalid completion responds with ready. updateActivity closes configuration and skips remaining steps. This implementation uses one step. `destroy` is documented for runningModal only, so it is not used as a configuration Cancel API.
- [Custom Activity Configuration](https://developer.salesforce.com/docs/marketing/marketing-cloud/guide/custom-activity-config.html): workflowApiVersion 1.1, Rest activity type, execute argument arrays, lifecycle URLs, and configModal/wizard configuration. The bundled template uses these definitions with explicit host/key placeholders.
- [How Data Binding Works](https://developer.salesforce.com/docs/marketing/marketing-cloud/guide/how-data-binding-works.html): binding is evaluated at runtime and is case-sensitive. Expressions are not resolved during save/publish/validate. This implementation retains source casing and does not perform Entry DE record retrieval.
- [Build Custom Activities and Events](https://developer.salesforce.com/docs/marketing/marketing-cloud/guide/creating-activities.html) and [Example REST Activity](https://developer.salesforce.com/docs/marketing/marketing-cloud/guide/example-rest-activity.html): hosted UI, configuration, Postmonger, and root index.html form the custom activity.

The reference's Event binding example uses the Event namespace and event key. Schema extraction adapters and nested-path support are application logic and require confirmation with actual tenant payloads. No undocumented metadata request event or invented token-based client lookup has been added.
